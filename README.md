# Dayline

Windows PC에서 오프라인으로 사용하는 캘린더 중심 To-Do 데스크톱 앱 프로토타입입니다. Electron과 React로 만들었으며, 인터넷이나 별도 서버 없이 일정 데이터와 위젯 위치를 기기에 저장합니다.

## 구현된 핵심 기능

- 월간 캘린더 위에 상위 일정만 표시하고, 여러 날에 걸친 일정은 주 단위로 이어진 하나의 바로 표현
- 토요일은 파란색, 일요일과 대한민국 공휴일은 빨간색으로 표시하며 토요일 공휴일은 빨간색을 우선 적용
- 캘린더를 드래그해 시작일~마감일 범위를 선택하고, 여러 날에 걸친 일정을 양 끝 날짜를 포함해 표시
- 이전·다음 달 이동과 연·월 직접 선택
- 선택한 날짜/기간을 새 일정의 기본값으로 두고, 사용자가 `시간도 지정`을 켰을 때만 시간 입력 노출
- 일정 좌클릭: 상세 내용 확인과 제목·기간·시간·메모·태그·세부 할 일 수정
- 일정 우클릭: 활성 일정은 즉시 비활성화, 비활성 일정은 `최근 삭제`로 이동
- 비활성화해도 일정의 정렬 위치를 유지하고, 기존 일정 색상을 옅게 표시
- 세부 할 일을 각각 완료할 수 있으며, 모두 완료하면 상위 일정도 자동 비활성화
- 상위 일정의 비활성화·삭제·복구를 세부 할 일과 함께 처리
- 선택한 날짜에 제목·마감·색상 형식이 없는 여러 줄 `퀵 노트` 작성
- 퀵 노트는 우측 패널과 위젯에서 관리하며 캘린더에는 표시하지 않음
- 우측 패널과 위젯에서 일정/퀵 노트 영역 높이를 드래그하거나 키보드로 조절하고, 각 영역을 독립적으로 스크롤
- 우측 패널의 일정과 퀵 노트를 오른쪽 핸들로 드래그하거나 `Alt+↑/↓`로 재정렬
- 캘린더 일정도 바 오른쪽 핸들로 드래그하거나 `Alt+↑/↓`로 순서를 변경하고 재실행 후 유지
- 캘린더 일정 바 본문을 다른 날짜로 드래그해 기간과 세부 정보를 유지한 채 일정 이동
- 9개의 기본 색상을 이름 변경 가능한 태그로 제공하고, 사용자 지정 이름·색상의 태그를 추가해 일정에 재사용
- 좌측 태그 필터에서 여러 태그를 OR 조건으로 선택해 캘린더와 우측 일정을 필터링
- 좌측 메뉴는 접고 펼칠 수 있으며 반복 일정·태그 필터·태그 설정·화면 설정으로 구분하고, 최근 삭제는 하단에서 바로 열기
- 앱 실행 시 공개 GitHub Releases의 최신 안정 버전을 확인하고, 좌측 `업데이트 확인 및 업데이트` 메뉴에서 수동 확인·다운로드·재시작 설치
- 앱 글자 크기(85~150%)와 전체 테마 강조색을 설정하고 메인 창·위젯에 함께 적용
- `반복 일정` 메뉴의 추가·수정 버튼으로 날짜 입력이 없는 전용 팝업을 열어 기간·시간·태그·메모·세부 할 일이 포함된 템플릿을 관리
- 반복 일정은 우측 핸들로 순서를 바꾸고, 템플릿 본문을 캘린더 날짜로 드래그하는 동안 메뉴가 비켜난 뒤 드롭 완료 시 자동으로 다시 열림
- 새 일정 작성 중 양식 밖을 클릭하면 변경 사항을 저장해 추가할지 작성 취소할지 확인
- 상세 화면의 내용·활성 상태 변경은 `변경 저장` 때만 반영되며, `취소` 시 모두 폐기
- 상세 화면의 `제거`는 확인 후 실행하고, 우클릭 제거는 확인 없이 즉시 실행
- 비활성 일정은 취소선과 구분 색상으로 캘린더에 유지
- 삭제 직후 실행 취소 및 상태 변경 직후 되돌리기
- 삭제 시점부터 30일 동안 제목, 날짜, 시간, 활성·비활성 상태를 보존하고 원상 복구
- 별도 데스크톱 위젯 창
  - 창 이동, 가장자리 크기 조절
  - 위치·크기 잠금
  - 항상 위 고정 전환
  - 기본 크기와 화면 우측 상단 위치로 초기화
  - 마지막 위치·크기·고정 상태 자동 복원
  - 다중 모니터 구성이 바뀌어도 화면 안으로 위치 보정
  - 상위 일정과 세부 할 일, 선택한 날짜의 퀵 노트를 함께 표시
  - 일정/퀵 노트 영역 크기 조절과 독립 스크롤
- 메인 창과 위젯의 로컬 데이터 실시간 공유
- Electron에 내장된 SQLite DB로 일정·퀵 노트·태그·화면 설정·반복 일정 템플릿과 계정 확장 메타데이터를 트랜잭션 저장
- 우주항공청 월력요항 기반 대한민국 공휴일 데이터(현재 2018~2027)를 앱에 포함해 오프라인으로 표시
- 기존 `dayline-data.json` 일정은 최초 실행 시 자동 이전하고 원본 백업 보존
- 최초 실행용 예시 일정과 복구 예시 제공

## 개발 실행

개발 환경은 Windows 10/11과 `node:sqlite`를 기본 제공하는 Node.js 22.13 이상입니다. 설치된 앱은 Electron에 SQLite를 포함하므로 사용자 PC에 Node.js가 필요하지 않습니다.

```powershell
npm install
npm run build:icon
npm run dev
```

## 검증

```powershell
npm test
npm run build
npm run qa:database
npm run qa:capture
```

- `npm test`: 기간·정렬·태그·템플릿 도메인, 활성·비활성 전환, JSON/v1/v2→SQLite v3 이전, 필드 단위 동시 변경과 정확한 30일 경계 조건 검증
- `npm run build`: TypeScript 검사와 프로덕션 렌더러 빌드
- `npm run qa:database`: 실제 Electron의 `node:sqlite`, v3 스키마·인덱스, preload IPC와 메인·위젯 동시 저장 검증
- `npm run qa:capture`: 실제 Electron 렌더러에서 기간 선택, 정렬, 태그·필터, 템플릿, 분할 패널, 상세·우클릭 동작과 최소 창 레이아웃을 점검

## Windows 설치 파일 만들기

```powershell
npm run dist:setup
# 또는 Setup + Portable을 모두 만들려면
npm run dist:win
```

`npm run dist:setup`은 첫 번째 파일만, `npm run dist:win`은 다음 두 파일을 `release` 폴더에 생성합니다.

- `Dayline-Setup-<version>-x64.exe`: 설치 경로를 고를 수 있고 바탕화면·시작 메뉴 바로가기를 만드는 NSIS 설치 프로그램
- `Dayline-Portable-<version>-x64.exe`: 설치 없이 실행하는 포터블 프로그램

두 결과물 모두 Electron 런타임과 모든 화면 자산을 포함하므로 설치와 사용에 인터넷 연결이 필요하지 않습니다. 프로토타입은 코드 서명을 하지 않았기 때문에 다른 PC에서 처음 실행할 때 Windows SmartScreen 경고가 나타날 수 있습니다.

## 앱 내 업데이트와 GitHub Release

앱 내 자동 업데이트는 **NSIS Setup으로 설치한 Windows 버전만** 지원합니다. Portable 버전과 개발 실행에서는 업데이트 메뉴가 지원되지 않는 이유를 안내하며, 새 Portable 파일을 직접 교체해야 합니다.

기존 버전에는 업데이트 기능 자체가 없으므로, 이 기능이 처음 포함된 버전은 Setup 파일을 한 번 직접 내려받아 설치해야 합니다. 그 버전부터는 앱 실행 시마다 최신 안정 Release를 확인하고, 알림 또는 좌측 `업데이트 확인 및 업데이트` 메뉴에서 다운로드한 뒤 재시작하여 설치할 수 있습니다.

Release를 게시할 때는 다음 조건을 지켜야 합니다.

- `package.json`의 버전을 올리고 같은 버전의 태그(예: `vX.Y.Z`)로 GitHub Release를 생성
- Draft나 Pre-release가 아닌 최신 안정 Release로 게시
- `electron-builder`가 만든 `latest.yml`, `Dayline-Setup-<version>-x64.exe`, Setup의 `.blockmap` 파일을 모두 Release asset으로 업로드
- Setup 파일 이름을 임의로 바꾸거나 `latest.yml`만 이전 버전으로 남겨두지 않기

Release 본문은 기능 범위별 제목과 구체적인 항목으로 작성합니다. 사용자가 업데이트를 선택하면 앱이 현재 버전과 대상 버전, 승인 시각, 확인된 릴리스 노트를 로컬 SQLite 메타데이터에 먼저 기록합니다. 새 버전이 실제로 실행된 뒤에는 기록한 버전보다 높고 현재 설치 버전 이하인 모든 안정 Release 본문을 GitHub에서 다시 조회해 버전 순서대로 함께 표시합니다. 일시적으로 조회하지 못해도 다운로드 전에 저장한 노트를 유지하고, 다음 실행 또는 수동 업데이트 확인 때 다시 조회합니다. 이 이력은 해당 PC에만 저장되며 일정 데이터의 동기화 revision이나 outbox에는 포함되지 않습니다.

```markdown
[반복 일정 메뉴]
- 템플릿을 캘린더로 드래그할 때 메뉴가 날짜를 가리지 않도록 수정
- 템플릿 추가와 수정을 전용 팝업으로 통일

[퀵 노트]
- 추가 버튼과 개수 표시 위치를 정리
```

업데이트 확인과 다운로드에는 인터넷 연결이 필요합니다. 연결할 수 없으면 기존 앱과 로컬 데이터는 그대로 유지되며 나중에 다시 확인할 수 있습니다. 설치형 앱에서 사용자가 업데이트를 승인하면 다운로드 완료 후 설치 화면 없이 업데이트하고 자동으로 앱을 다시 엽니다. 수동으로 Setup을 실행하는 최초 설치 화면은 그대로 유지됩니다. 업데이트는 `%APPDATA%`의 Electron `userData` 폴더에 있는 `dayline.db`를 덮어쓰지 않으므로 일정·퀵 노트·태그·설정·반복 일정이 보존됩니다. 그래도 중요한 배포 전에는 데이터 파일 백업을 권장합니다.

업데이터 변경을 배포하기 전에는 일반 테스트와 빌드에 더해 `npm run qa:update`, `npm run qa:database`, `npm run qa:capture`를 실행합니다. 릴리스 직전에는 실제 공개 Release API가 건너뛴 안정 버전의 본문을 빠짐없이 반환하는지, 생성된 `latest.yml`이 같은 빌드의 Setup 파일명·크기·SHA-512와 일치하는지도 확인합니다.

## 데이터 위치

설치 버전과 Portable 버전은 Electron의 Windows `userData` 폴더 아래에 다음 파일을 저장합니다.

- `dayline.db`: 일정, 세부 할 일, 퀵 노트, 태그, 화면 설정, 반복 일정 템플릿, 로컬 프로필과 향후 동기화 상태
- `dayline.db-wal`, `dayline.db-shm`: 앱 실행 중 SQLite가 사용할 수 있는 트랜잭션 보조 파일
- `dayline-data.json.pre-sqlite-backup`: 기존 JSON 일정이 있었을 때 한 번 생성되는 이전 전 백업
- `dayline-data.json.migration-failed-backup`: 기존 JSON을 읽지 못했을 때 원본과 함께 보존되는 복구용 백업
- `dayline-window-state.json`: 위젯 위치, 크기, 항상 위, 잠금 상태

개발 실행 데이터는 `%APPDATA%\Dayline Dev`로 분리됩니다.

## 계정 연동 확장 설계

현재 앱은 서버 없이 `guest` 로컬 프로필로 동작합니다. DB에는 추후 Google·Kakao·Naver 등의 로그인 제공자를 연결할 수 있도록 `profiles`, `auth_identities`, `devices`, `sync_outbox`, `sync_cursors` 구조가 포함되어 있습니다.

- SNS 계정은 이메일이 아니라 제공자의 고유 `provider_subject`로 구분
- 기존 오프라인 일정은 같은 프로필에 서버 사용자 ID를 연결해 그대로 유지
- 메인 창과 위젯은 전체 배열을 덮어쓰지 않고 변경된 필드만 SQLite 트랜잭션으로 반영
- 일정·퀵 노트뿐 아니라 태그·화면 설정·반복 일정 템플릿도 향후 동기화 아웃박스에 담을 수 있도록 설계
- 실제 OAuth 토큰은 현재 저장하지 않으며, 연동 구현 시 Windows DPAPI 또는 Credential Manager로 보호
- 서버 동기화를 추가할 때 PostgreSQL은 서버의 중앙 저장소로 사용하고 SQLite는 오프라인 캐시로 유지

## 프로토타입 범위

현재 위젯은 사용성이 좋은 `항상 위` 또는 일반 창 모드입니다. Windows의 WorkerW에 붙어 모든 일반 창 뒤, 바탕화면 아이콘과 같은 레이어에 상주하는 네이티브 데스크톱 위젯은 Electron 기본 API가 아니므로 후속 Windows 네이티브 연동 범위로 남겨두었습니다.
